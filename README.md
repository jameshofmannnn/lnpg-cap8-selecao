###Análise comparativa Q1###

Analisando as saídas, percebi o quanto Python é uma linguagem mais receptiva para quem está aprendendo a programar, como eu. Python é mais "enxuto", não usa muitos caracteres, simplificando ao máximo o código. Isso é bem-vindo pois facilita e causa menos impacto inicial para quem está dando os seus primeiros passos no mundo da programação.

Já o Java já tem aquele "peso" visual logo no primeiro momento. Ele exige mais detalhes, mais caracteres que para pessoas que começaram a programar em python (como eu) se torna estranho e até desnecessário (pelo menos acreditamos no começo). O número de linhas também é maior, justamente porque há mais caracteres.

A linguagem Swift achei bem parecida com Java, mudando só alguma nomeclaturas, mas a estrura é praticamente a mesma (pelo menos nesse exemplo de loop). Por exemplo, em vez de usar "int" para declarar a variável, em Swift usa-se "var". Em Java usa-se os parênteses para criar um laço e incluir a condição inicial (ex.: k <=10>), mas Swift não os utiliza.

Pesquisando, vi que nessa linguagem o loop não é feito do jeito "normal" como é mais conhecido. Tem que usar uma função para chamar ela mesma. Parece bem complicado e confesso que não me interessei em me aprofundar.

Assim, Python vence como a mais prática, na minha opinião, por exigir menos caracteres e organizar o código de maneira mais direta e racional (me refiro ao que parece ser menos complicado, mais prático). As demais exigem mais trabalho, mas gostei de entender as especifidades de cada uma.


###Análise comparativa Q2###

A linguagem C é muito completa e exige muitas informações para serem adicionas explicitamente, com mais detalhes, o que exige mais conhecimento e bem mais lógica. Dá muito mais trabalho do que Python, que é mais simplificado em caracteres e dificuldade de lógica. E o tamamho do código e muito maior que as demais. Acho que seja muito trabalho para algo que poderia ser mais prático em outra linguagem.

Em Ruby ficou mais prático, pois o código ficoi mais limpo e com menos linhas. Não precisa a mesma dificuldade para entender o que foi feito em comapração com C. Juntando vários valores na mesma limpa deixe mais simples e compreensível.

Agora o Erlang foi muito estranho. É como se o pandrão e a sintaxe mudasse completamente dos padrões das outras linguagens de programação. Fica tudo bem mais repetitivo, não permitindo juntar partes do código para poupar linhas e caracteres. Não achei tão chocanto quanto Huskel, na verdade é bem organizada. Só foge do padrão do que somos acostumados com Python, Java, etc.

Então Ruby ganha em facilidade e claridade. Não é necessário tanto trabalho como em C e nem foge dos padrões já conhecidos de várias outras linguagens.
